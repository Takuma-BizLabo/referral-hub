# 11. 候補ピックアップ

> 一言で：ベンダーごとに「候補の条件」（従業員数・役職クラス・部署・業種・地域・除外企業）を入れておくと、まだ提案していない人事を「条件に合う／要確認／合わない」に分けて上から出す。

## できること（使う人の目線）

- ベンダーの編集画面で「候補の条件」を入れる（空の項目は問わない）。
- ベンダー詳細の「＋ 提案した人事を追加」を開くと、条件と単価表に合う人事が上に並ぶ。
- 「条件に合う」「要確認（データが足りない）」「すべて」で切り替え、チェックして「選んだ ○ 人を提案に追加」で一括登録（→ 01・02 の紹介案件になる）。
- 各行に、合う理由・確認すること・合わない理由が小さく出る（例：「従業員数 217名 ／ 部長クラス ／ 人事部」「従業員数が不明」）。
- 返信なしの人事（12）は既定で隠す。「返信なしを隠す」を外すとグレーで一番下に出る。
- 閉じた状態でも「候補の条件に合う人事 ○ 人・要確認 ○ 人」を表示。

## 画面と操作

- ベンダー編集（referral-hub：`/vendors/[id]/edit`）：「候補の条件（候補ピックアップに使う）」の枠。
  - 従業員数（以上）・従業員数（未満）：数値。
  - 役職クラス：チェックボックス（代表取締役・会長・顧問・役員・取締役クラス・本部長クラス・部長クラス・課長クラス・主任・係長クラス・一般社員）。
  - 部署（例：人事）・業種（「、」区切り）・地域（「、」区切り）・除外する企業（1行1社）。
- ベンダー詳細（`/vendors/[id]`）の提案ピッカー：
  - 上に「候補の条件：従業員数 100〜999名 ／ 役職 部長クラス・課長クラス ／ 部署「人事」 条件を変える」。条件も単価表もないときは「全員を表示しています。条件を入れる」。
  - チップ「条件に合う（n）」「要確認（n）」「すべて（n）」（`.chip` / `.chip-active`）、検索欄、「返信なしを隠す」。
  - 行のバッジ：合う `bg-emerald-50 text-emerald-800`、要確認 `bg-amber-50 text-amber-800`、合わない `bg-gray-100 text-gray-500`、返信なし `bg-gray-200 text-gray-600`（行は `bg-gray-50 opacity-60`）。
  - 右端に見込みの報酬（単価表 → ベンダー単価。決まらなければ「未定」）。

## データ

`vendors.criteria`（JSON、空は NULL）：

| キー | 型 | 意味 |
|---|---|---|
| minEmployees | number \| null | 従業員数の下限（以上） |
| maxEmployees | number \| null | 従業員数の上限（未満）。下限より大きいこと |
| classes | string[] | 役職クラス（空＝問わない） |
| dept | string \| null | 部署のキーワード |
| industries | string[] | 業種のキーワード（どれかを含めば可） |
| regions | string[] | 地域のキーワード（どれかを含めば可） |
| excludeCompanies | string[] | 除外する企業（株式会社などを除いて比べる。部分一致） |

SQLite 例：

```sql
ALTER TABLE vendors ADD COLUMN criteria TEXT; -- JSON 文字列（NULL＝条件なし）
```

## 決まり（ロジック）

`matchCandidate(criteria, feeRules, contact)` → `{ level, ok[], check[], ng[] }`

- 項目ごとに「合う（ok）」「不明（check）」「合わない（ng）」を判定。
  - 除外企業：会社名を正規化（法人格・空白を除く・小文字）して一致または包含 → ng。
  - 従業員数：`parseEmployeeSize`（02 の単価表と同じ読み取り）。読めない → check。範囲内 → ok。範囲にまたがる → check。重ならない → ng。
  - 役職クラス：`splitTitle(title).cls`（03）。不明 → check。
  - 部署：`contactDept`（関係性メモ「部署: 人事部」や氏名の括弧）＋役職の文字にキーワードを含むか。分からなければ check。
  - 業種・地域：空 → check、キーワードを含む → ok、それ以外 → ng。
  - 単価表（ある場合）：`judgeFee` が matched → ok（金額）、outside → ng、ambiguous/unknown → check。
- level：ng が1つでもあれば `no`、無くて check があれば `maybe`、それ以外は `match`。条件も単価表もなければ全員 `match`。
- 並び：match → maybe → no、同じ段では返信なしを最後。
- 対象は「有効」で、そのベンダーにまだ紹介案件がない繋がり（最大1000件）。

## 移植のポイント

- `candidates.ts`・`fee-table.ts`・`title.ts` はそのままコピーできる。
- 条件は JSON 1列で持つ（列を増やさない）。読み出しは必ず `parseCriteria` を通す。
- 一覧の判定は画面側で全件に対して行う（件数が多くなったら、従業員数・地域だけ先に SQL で絞る）。
